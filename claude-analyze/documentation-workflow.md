# 技术分析文档生成指南

## 文档存储规范

### 目录结构
```
claude-analyze/
├── README.md                           # 文档索引和导航
├── architecture-overview.md            # 项目架构总览
├── engine-startup-analysis.md          # 引擎启动流程分析
├── spidermonkey-mod-development.md     # SpiderMonkey Mod开发指南
├── initvfs-functionality-analysis.md   # VFS初始化功能分析
└── [future-analysis-files.md]          # 未来的分析文档
```

### 命名约定
- 使用小写字母和连字符分隔
- 文件名应清晰描述分析内容
- 添加 `-analysis.md` 后缀表示技术分析文档

### 文档格式标准
每个技术分析文档应包含：

1. **概述部分**
   - 分析目标的简要描述
   - 在项目中的位置和重要性

2. **详细分析**
   - 代码结构和实现细节
   - 关键函数和类的说明
   - 设计模式和架构决策

3. **技术要点**
   - 核心概念解释
   - 重要的技术细节
   - 性能和安全考虑

4. **文件引用**
   - 相关源代码文件路径
   - 行号引用（如适用）
   - 配置文件位置

5. **相关系统**
   - 依赖关系说明
   - 与其他组件的交互
   - 在整体架构中的作用

## 分析类型分类

### 系统架构分析
- 整体架构设计
- 模块间依赖关系
- 设计模式应用

### 功能实现分析
- 具体功能的实现方式
- 算法和数据结构选择
- 性能优化技术

### 启动流程分析
- 系统初始化顺序
- 依赖关系建立
- 错误处理机制

### 开发工具分析
- 构建系统配置
- 调试和测试工具
- 开发效率优化

### 扩展性分析
- Mod系统设计
- 插件架构
- API设计原则

## 文档更新流程

### 新增分析文档
1. 在 `claude-analyze/` 目录创建新的 `.md` 文件
2. 按照标准格式编写分析内容
3. 更新 `README.md` 中的文档索引
4. 在相关文档中添加交叉引用

### 更新现有文档
1. 直接修改对应的分析文档
2. 更新修改日期和版本信息
3. 如有重大变更，在 `README.md` 中标注

### 文档维护
- 定期检查文档与代码的一致性
- 更新过时的信息和链接
- 添加新发现的技术细节

## 质量标准

### 内容要求
- 准确性：基于实际代码分析，避免推测
- 完整性：覆盖分析目标的主要方面
- 可读性：使用清晰的结构和专业术语
- 实用性：提供有价值的技术洞察

### 格式要求
- 使用标准 Markdown 语法
- 代码块使用适当的语法高亮
- 适当使用列表、表格和引用
- 保持一致的标题层级

## 工具和自动化

### 代码引用
- 使用具体的文件路径和行号
- 提供代码片段的上下文
- 链接到相关的头文件和实现

### 图表支持
- 使用 Mermaid 图表表示架构关系
- ASCII 艺术用于简单的示意图
- 表格用于对比和汇总信息

## 协作和版本控制

### 版本标识
每个文档应包含：
- 创建日期
- 最后修改日期
- 基于的代码版本 (如 0.28.0)

### 贡献者信息
- 分析工具：Claude Code
- 生成时间戳
- 相关的项目里程碑

**注意**: 这是一个活跃维护的文档集合，会随着代码库的发展持续更新。所有技术分析都将遵循这些标准存储在 `claude-analyze/` 目录中。
